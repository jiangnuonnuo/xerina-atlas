## Q1

### 题干
在 Java 中，创建并启动一个线程有哪几种常见方式？请列举并简述各自的特点和适用场景。

### 开卷
Java中创建并启动线程的常见方式及其特点适用场景
- 继承Thread类：重写run()方法，调用start()启动。特点：实现简单直观；受Java单继承限制，无法再继承其他类，且Thread子类实例无法共享。适用：简单、独立的线程任务，无需复用的场景
- 实现Runnable接口：实现run()方法并传入Thread构造器启动。特点：避免单继承限制，接口灵活性高；多个线程可共享同一Runnable实例，便于资源共享。适用：多线程处理同一共享资源（如票务系统），实现线程与任务解耦

- 使用ExecutorService线程池：通过工厂类创建线程，复用线程资源。特点：线程复用、控制并发数、提供生命周期管理、支持定时任务。适用：高并发服务端应用，避免频繁创建销毁线程的开销

## Q2

### 题干
在 Java 中，`volatile` 关键字经常被拿来和 `synchronized` 对比。请简述：**`volatile` 能保证线程安全吗？为什么？** 它与 `synchronized` 在可见性和原子性上分别有什么区别？

### 开卷
简述 volatile 是否能保证线程安全、原因，以及其与 synchronized 在可见性、原子性上的区别
- volatile 无法保证线程安全：仅能保证变量的可见性与有序性，不保证原子性，对于读-改-写类复合操作（如 i++、count+=1）仍会出现竞态条件导致线程不安全
- volatile 保证可见性的实现原理：通过内存屏障实现，写 volatile 变量时插入 Store 屏障强制将工作内存修改刷新到主内存，读时插入 Load 屏障强制从主内存加载最新值，保证修改对所有线程立即可见
- 可见性对比：volatile 与 synchronized 都能保证可见性，但实现机制不同：synchronized 通过「释放锁时刷回主内存、获取锁时重新加载主内存」的 happens-before 规则保证可见性，且同步块内所有变量的修改均对其他线程可见；volatile 仅保证自身修饰变量的可见性，不涉及线程阻塞
- 原子性对比：volatile 仅能保证单次读/写操作的原子性，无法保证复合操作的原子性；synchronized 通过互斥锁保证同一时刻仅有一个线程执行同步代码块/方法，能保证任意操作的原子性
- 二者特性与适用场景差异：volatile 是轻量级同步机制，无线程阻塞与唤醒开销，仅适用于仅需保证变量可见性和有序性的场景（如状态标记量）；synchronized 是重量级锁，有线程调度开销，但能同时保证可见性、原子性和有序性，适用于需要互斥访问的复合操作场景

### 题干
在并发编程中，**线程池**是管理线程的核心工具。请说说：**Java 中创建线程池最常用的类是哪一个？** 它有哪些核心参数？如果不合理设置参数，可能会带来什么问题？

### 开卷
Java中创建线程池最常用的类、核心参数及参数不合理设置的影响
- Java中创建线程池最常用的核心类是ThreadPoolExecutor，可通过Executors工具类快速封装不同特性的线程池
- 核心参数共7个：corePoolSize（核心线程数）、maximumPoolSize（最大线程数）、keepAliveTime（非核心线程空闲存活时间）、unit（存活时间时间单位）、workQueue（任务等待队列）、threadFactory（线程创建工厂）、handler（任务拒绝策略）
- 核心线程数设置过小会频繁创建销毁线程增加系统开销，设置过大则过度占用CPU、内存等系统资源

- 无界任务队列（如无界构造的LinkedBlockingQueue）会导致任务无限积压，最终引发内存溢出（OOM）
