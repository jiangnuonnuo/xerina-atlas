# 实习讲解与简历表达

## 一句话介绍

我参与的是一个字段目录平台：它把业务页面上分散的字段定义沉淀为可维护的层级目录，并通过一致性快照和异步导出交付给下游使用；在上游探索了 DOM-first 的页面字段采集与 Agent 辅助层级解析。

这里的关键词是“字段定义”，不是“业务数据爬取”。我处理的是页面结构和字段语义，例如“订单中心 → 订单列表 → 筛选条件 → 创建时间”，而不是订单号、手机号或接口返回值。

## 项目背景怎么讲

随着业务页面增多，字段信息通常靠人工从页面抄到表格里：同一字段在不同页面路径下重复出现，页面改版后旧字典不知道何时失效，导出大目录时又会卡住。平台的目标不是造一个更花哨的表格，而是建立一条能持续维护的字段资产链。

我把问题拆成四件事：

- 让页面字段有可追溯的来源证据；
- 让目录树在新增、移动、删除、恢复时保持正确；
- 让字典导出在大规模数据下仍能恢复和追踪；
- 对 Agent 的能力边界做验证，避免让模型把“看起来像”直接写成事实。

## 90 秒讲法

“我参与了一个字段目录平台，核心是把业务页面上的菜单、页签、分组、字段和指标整理成可维护的层级目录。原来的输入方式是前端按缩进把固定层级传给后端，能用，但对页面变化依赖人工。

我在目录治理和交付链路上重点关注了结构正确性与可恢复性：目录把直接父级关系和祖先关系分开维护，支持创建、移动、软删除和恢复，并用影响范围锁和版本校验防止并发把树改坏；交付侧采用一致性快照、异步任务、检查点和流式文件生成，避免大导出占满内存或断线后从头来。

上游我还做了自动化方向的技术验证。纯 Agent 浏览页面会漏掉未展开的 Tab、滚动区域或受权限影响的内容，所以方案转成 DOM-first：人工可以用 Easy Copy DOM 指定区域；自动模式由 Agent 规划页面状态，但浏览器工具做确定性 DOM 取证。Agent 再负责字段和层级语义判断，结果必须带 DOM 证据、规则校验和人工预览，才能进入目录。”

## 简历表达模板

以下表达应只选用自己实际参与、能追问到底的部分；“技术验证”和“方案设计”不要写成已生产上线。

**项目描述**

字段目录平台｜后端 / 平台研发实习

- 参与建设页面字段目录治理与字典交付链路，将菜单、页签、分组、字段和指标统一沉淀为可维护的层级资产。
- 设计目录树的结构约束与生命周期策略，覆盖节点创建、批量导入、移动、软删除、恢复及并发一致性校验。
- 梳理异步导出任务的快照、检查点、重试与流式写入机制，提升大规模字段字典的可恢复交付能力。
- 完成页面字段自动采集方向的技术验证：发现纯 Agent 页面探索存在状态漏采，提出 DOM-first 的“确定性取证 + Agent 语义解析 + 人工确认”闭环。

**一条更偏技术的表述**

围绕字段目录平台的“采集—解析—治理—交付—变更”闭环，设计树结构一致性、可恢复异步任务与 DOM-first Agent 辅助解析方案，使页面字段资产具备来源证据、人工可校正和持续演进能力。

## 个人价值应该落在哪

| 价值点 | 面试时怎么落地解释 |
| --- | --- |
| 不是只做功能 | 先定义字段资产范围、成功条件和失败状态，避免“导出了就算完成” |
| 能处理复杂结构 | 把树的写入、路径读取、移动影响和删除恢复看作同一个一致性问题 |

## 高频追问与回答骨架

### 为什么不直接让 Agent 读 HTML 然后入库？

因为页面内容是不可信输入，且模型容易把隐藏区域、示例文本或视觉相邻关系误判为目录事实。正确顺序是：DOM 证据先限定可见事实；模型只做受限语义推理；规则校验阻止结构错误；低置信度结果由人工确认。模型当然可以有想法，但没有证据，想进库？门都没有。

### 纯 Agent 自动采集为什么不够？

技术验证中发现，页面完整性取决于“状态覆盖”，不只是首次渲染的 HTML。Tab 未切换、折叠区未展开、懒加载未触发、角色没有权限、跨域 iframe 或画布内容，都可能让 Agent 在信息不完整时结束。因此 Agent 适合规划探索和判断语义，而浏览器 / DOM 工具更适合执行点击、滚动、稳定检测和快照采集。

### 树结构最难的地方是什么？

难点不是插入一个节点，而是移动和删除。移动会影响整个子树的路径与祖先关系；并发操作又可能造成环、重复同级名称或超深层级。处理方式是先锁定影响范围，再做结构校验，在同一事务中更新直接父级关系和祖先关系，并用版本信号让读侧刷新。

### SSE 断开会不会导致解析任务丢失？

不会把 SSE 当成任务本体。SSE 用于把阶段进度和预览结果推给前端；任务输入、状态、检查点和最终结果独立持久化。连接断开后，前端可以重新订阅，后台从检查点继续或查询任务真实状态。

### 你如何衡量方案是否可用？

至少看四类指标：字段覆盖度、结构正确率、人工修订率和任务恢复率。覆盖度看已发现页面状态是否都有快照或明确跳过原因；结构正确率看无环、深度、同级唯一和证据绑定；修订率用来定位规则或提示上下文缺口；恢复率验证重试是否真的从检查点续跑。

## 诚实而有力的边界表达

当被问到 Agent 自动采集是否已经上线，可以直接说：

“目录治理和交付链路已有工程实现；自动采集方向我完成了可行性验证，并根据纯 Agent 漏采的结论沉淀了 DOM-first 方案。它的价值在于明确了下一步实现不能只提升模型能力，还要建设页面状态覆盖、证据和人工回路。”

这比一句“我做了全自动 AI 抓取”更经得起追问，也更像工程师。
