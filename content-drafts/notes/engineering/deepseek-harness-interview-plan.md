## 1. 需求与推广定位分析

### 1.1 需求原点：练八股的三个断裂

不是「缺一个刷题网站」，而是三个更具体的断裂：

| 断裂 | 具体表现 | 现在的补救方式 |
| --- | --- | --- |
| 环境断裂 | 已经在 DSH 里写代码、对话、选模型；练八股要切到另一个产品 | 新开网页 / 复制粘贴题目 |
| 角色混叠 | 把面试官塞进正在写代码的对话，或让标准答案、评分和提问挤在同一段气泡里 | 手动切对话、事后自己评分 |
| 结果不留 | 面完就散，第二天全忘，复盘只能翻聊天记录 | 手动整理成 md |

一句话痛点：**练八股这件事，和「写代码的地方」「留下来的东西」是断开的。**

### 1.2 用户画像

**主用户：准备秋招、找实习的同学。**

- 已经在用 AI 编码工具写代码，DSH（或同类 Harness）是日常环境；
- 需要系统练八股（Java 并发 / MySQL / Redis / MQ / Spring…），但不想再开一个独立产品；
- 想要「被系统地问、当场知道差在哪、练完还能留下来复习」；
- 对装插件、跑命令不排斥，但不接受复杂配置。

**次用户（少量篇幅照顾）**：对 DSH 插件开发、OpenSpec 流程感兴趣的开发者——他们在第八部分停留。

**不是给谁用**：HR、面试官后台、多人协作场景。全文不提。

### 1.3 产品定义（一句话，全文反复回指）

**`interview-dsh` 是跑在 DeepSeek Harness 上的八股专项陪练插件：考场对话当面试官，右侧面板当教练，问答落盘成可导入笔记库的 Markdown。**

三个必须讲清的否定式定义：

- **不是独立聊天应用**：说话只发生在 DSH 原对话里，面板没有输入框、没有消息列表、没有气泡。
- **考场不是正在写代码的那条对话**：点开始后在项目分组下**新开**一场面试官会话。
- **是开卷陪练，不是闭卷考场**：每题先给开卷要点，作答后立刻给对照与五维。

### 1.4 三个表面与角色分工

| 表面 | 归属 | 角色 | 用户感知 |
| --- | --- | --- | --- |
| 输入栏右侧「面试」按钮 | 宿主槽 `conversation.input.right` | 入口 | 打开面板，不做任何副作用 |
| 考场对话（新开的 DSH 会话） | 宿主 | 面试官 | 提问、追问、提示、换题、结束 |
| 右侧插件面板 | 本插件前端 | 教练 | 开始练习、看开卷要点、看对照与五维、左右切回已答卡 |

数据只允许单向流动：**A（考场）的问答作为材料交给 B（面板）**，B 绝不回流到 A；B 的任何输出都不得进入气泡。

### 1.5 差异化：和三种现有练法比

| 现有练法 | 它的问题 | 本项目的做法 |
| --- | --- | --- |
| 独立八股刷题 / 面试网站 | 环境断裂，练完和代码库没有关系 | 长在编码环境里，档案落在当前工作区 |
| 直接把一段面试官 prompt 粘进对话 | 标准答案和提问挤在同一段气泡里；没有结构、没有留档 | 双会话隔离 + 卡片结构 + 落盘 md |
| 自己从零写一个面试 Web App | 要自己造运行时、双端通信、会话存储 | DSH 提供插槽与生命周期，插件只写业务 |

一句话价值主张：**不离开编码环境，就能被系统地问、被结构化地评、被自动地存下来。**

### 1.6 范围边界（明确不做）

- 不做项目深挖、不做混合模式——**当前只做八股专项**。
- 不做预置死题库：题目由模型按主题动态生成。
- 不做时长与倒计时、不做目录选择、不做面板上的「提示 / 跳过」。
- 不做场级长简报：简报 = 可切回的逐题评分卡。
- 不做音视频、云归档、面板里的 Markdown 编辑器 / 预览器。
- 不自建聊天表面：查不到官方 API 就标 `TODO` 并在面板给出可见失败。

### 1.7 五个关键设计决策及其代价

| 决策 | 为什么 | 代价 / 必须付出的复杂度 |
| --- | --- | --- |
| **双会话隔离** | 面试官不该看见评分与标准答；作答时不应被答案污染 | `workspaceId` 解析、会话复用判断、跨会话材料传递 |
| **新开考场会话而非注入当前对话** | 面试官不能污染正在写代码的上下文 | 必须解决「会话挂到哪个工作区」，否则掉进「未分组」 |
| **开卷 + 交卷即评** | 陪练的目的不是考倒人，是立刻知道差在哪 | 每题一次教练调用，需要看守与超时控制 |
| **卡片化而非长文** | 场末长文不可回看；卡片可切回、可留档 | 编号规则（Q1 / Q1.1 / Q2）、状态机、落盘渲染 |
| **落盘为纯 Markdown 到工作区** | 档案要能被 Obsidian / RAG 直接吃 | 必须走宿主 `ctx.fs` 沙箱，禁 `node:fs`；失败要面板可见 |

### 1.8 能力现状矩阵（写作时必须诚实标注）

| 能力 | 状态 | 落点 |
| --- | --- | --- |

### 1.9 形态定位：为什么做成插件，而不是一个独立应用

**判断前提**：面试陪练真正需要的能力，DSH 已经全都有了——会话的创建与流转、模型调用与配置、系统提示词装配、文件读写与沙箱、UI 插槽与生命周期、会话日志与恢复。**缺的只有「面试规则」和「教练面板」这一层业务。**

**结论**：**不要重建 Agent 与 Harness，也没有必要再去自己「指定」一套 Agent 和 Harness 的东西。**

DeepSeek Harness 本身就是一个**天然的 Harness 框架**——插件化底座、能力按需声明、UI 也是一等插件、`cordis.patch.yml` 声明式装配、append-only 轨迹可追溯。它交付的不是「一个聊天产品」，而是**一套可以被长能力的运行时**。

所以正确做法只有一条：**直接复用 DSH 已经做好的 Agent 与 Harness**，插件不去定义自己的会话模型、不去接自己的模型、不去拼自己的运行时；只在这一层之上补业务——**提供面试规则（人设、追问口径、评分维度）与教练面板（开卷要点、对照与五维、卡片化回看），以及档案落盘。**

一句话分工：**DSH 负责「怎么说」，插件负责「按什么规则说、怎么呈现、留下什么」。**

**插件只承担三件事**（其余全部交给宿主）：

| 插件承担的 | 具体内容 |
| --- | --- |
| 面试规则 | 面试官人设与提问/追问口径（提示词模板化）、五维评分与对照口径、开卷要点 |
| 教练面板 | 开卷要点、对照与五维、卡片化回看与滑动切题（只读呈现，不聊天、不评分） |
| 档案落盘 | 把本场 Q/A 写成可导入笔记库的纯 Markdown（`qa.md` / `summary.md` / `cards/*.md`） |

**明确不碰**：会话创建与流转、模型配置与密钥、气泡渲染、输入与发送、工具与沙箱策略、宿主 UI 布局。

**这条选择的代价**：不能改 DSH 核心；官方 API 形态只能实测确认；查不到就标 `TODO` + 面板可见失败，不许猜 API，更不许自建聊天绕过；面板永远是「教练」。

## 2. 文章写作规格：立意、对象、语气与纪律

### 2.1 立意

**一句话立意**：

> **练八股不用另开一个产品——我把面试官做进了你写代码的地方，开源了，装上就能用。**

三个支撑点（全文围绕，不得跑偏）：

1. **让读者用起来**：这是主目标。文章要让一个秋招同学读完就知道怎么装、怎么开一场、怎么把记录导进笔记库。
2. **讲清它为什么长这样**：为什么是插件、为什么复用 DSH 而不重建 Agent 与 Harness、为什么是开卷陪练——这部分给「为什么值得信」而不是炫技。
3. **它不是一次性的 AI 产物，而是一个按 SDD 规范长期推进的项目**：代码主要由 AI 产出，但每一刀都先写清「为什么改、改什么、怎么验收」再动手，做完就归档、成为下一刀的地基。所以它后面还能继续加能力（第九部分的方向不是画饼）。这部分用来建立信任——这项目能长期维护，也欢迎你一起共建。

**立意的三条边界**：

- 不是方法论文章：SDD / OpenSpec 只讲**这个项目实际怎么跑的**，不抽象成通用教程。
- 不是八股知识点文章：HashMap、MySQL 索引本身一个字都不讲。
- 不是 DSH 文档翻译：基础概念只给一句话 + 姊妹篇链接。

**读者读完应该做的两件事**：装上去开一场；顺手点个 star。

### 2.2 对象

| 读者 | 他们已经知道 | 他们不知道 / 想要 | 文章要给他的 |
| --- | --- | --- | --- |
| **主读者**：秋招 / 找实习的同学 | 八股是什么、什么叫追问、用过 AI 编码工具 | 练八股能不能留在编码环境里、练完的东西怎么复习 | 一条五分钟上手路径 + 一份可复习的留档方式 |
| **次读者**：对 DSH 插件 / OpenSpec 感兴趣的开发者 | Agent 与 Harness 的区别、Vibe Coding | 为什么做成插件、AI 怎么被夹住 | 第四部分的判断 + 第八部分的流程概览 |
| **不是给谁看** | HR、面试官后台、产品运营 | — | 全文不提后台、协作、商业化 |

### 2.3 定位

- **主定位：开源项目介绍 + 上手指南**（README 的展开版，但不复制 README）。
- **次定位：说明它是一个 SDD 规范驱动的长期项目**（第八部分）——不是「AI 一把梭写完」，而是有规范、有小步、有验收门槛地持续演进。
- **主线**：练八股的痛点 → 装上就能用 → 一场面试怎么走 → 记录怎么变成资产 → 它是怎么按 SDD 规范一步步长出来的 → 来一起玩。
- **不追求**：功能罗列完整、参数详解、API 手册、架构深挖。

### 2.4 语气与人格

- **人称**：第一人称「我」为主，面向读者用「你」。
- **口吻**：写给同学的口吻——亲切、具体、有用，先解决你的问题，再讲我的设计。
- **共鸣优先**：开场用真实练习场景切入（晚上练八股、面完就忘），不要从架构开始。
- **节奏**：每节首句给结论；能用表格不用长段落；步骤用编号清单，能照着做。
- **诚实**：没做完的写「在制 / 未验收」；不把方向写成承诺。
- **克制**：不喊「革命性 / 颠覆 / 最强」；介绍自己的项目可以有热情，但不浮夸。
- **号召**：star 引导自然放在两处（第一部分首次给地址时、第九部分结尾），不反复喊。

### 2.5 术语规范（全文统一，不许换词）

| 统一叫法 | 含义 | 禁止写法 |
| --- | --- | --- |
| 考场会话（会话 A） | 新开的、由面试官主导的那条 DSH 对话 | 「面试房间」「考试会话」「聊天室」 |
| 教练面板（会话 B） | 右侧插件面板 | 「侧边栏」「聊天面板」「评估页」 |
| 开卷要点 | 每题先给出的提示要点 | 「标准答案」「参考答案」 |
| 对照 | 作答后给的「已覆盖 / 未覆盖 / 评语」 | 「点评」「讲评」 |
| 五维 | 基础扎实度 / 原理理解 / 场景迁移 / 深度边界 / 表达清晰度 | 单独说「评分」要点明是五维 |
| 甲板 / 卡片流 | 本轮所有卡片的有序集合 | 「题集」「列表」 |
| 宿主 | DeepSeek Harness 本体 | 「平台」「框架」混用 |
| 一刀 | 一个 OpenSpec change | 「一次迭代」「一个版本」 |

- 代码符号（`systemPrompt.section`、`ctx.fs.resolve`、`shell.overlay`）用反引号，不翻译。
- 首次出现给全称：`DSH（DeepSeek Harness）`；面向主读者时，`Cordis`、`Typert`、`Trajectory` 这类词能不出现就不出现。

### 2.6 结构纪律

1. **结论前置**：每节第一句必须是这一节的结论。
2. **一节一事**：回答完立刻收，不夹带。
3. **表优先**：对比、清单、映射一律用表格；只有因果推导才用段落。
4. **图配文**：每张图下必须有一句「这张图说明什么」。
5. **回指**：核心定义（§1.3 产品定义、§1.9 形态定位）全文至少回指 2 次。
6. **不劝退**：主读者是找实习的同学，讲机制与流程时始终回到「这对你意味着什么」，不堆术语。

### 2.7 篇幅与配图规划（全文约 6000 字）

| 部分 | 篇幅 | 配图 |
| --- | --- | --- |

| 二 五分钟跑起来 | ~600 字 | 0–1 张 |
| 三 它到底是什么 | ~700 字 | 1 张（三表面） |
| 四 为什么做成插件 | ~600 字 | 1 张（复用 vs 自建） |
| 五 五个核心机制 | ~900 字 | 1 张（双会话流） |
| 六 一场面试走一遍 | ~900 字 | 6–7 张实机截图 |
| 七 记录变资产 | ~600 字 | 1 张（目录树） |
| 八 SDD 规范驱动的 Vibe Coding | ~700 字 | 0–1 张 |
| 九 后续方向 + 共建 | ~300 字 | 0 张 |
| 十 FAQ | ~300 字 | 0 张 |
| **合计** | **约 6100 字** | **11–13 张** |

### 2.8 禁用清单

- **不夸大**：不写「彻底解决」「完全替代」；不把方向写成已支持。
- **不编造**：没有使用数据就不写数据；缺事实时标 `[NEEDS_REVIEW]`。
- **不越界**：不写政治、公司隐私、密钥与内网地址；不把团队成果写成个人独创。
- **不注水**：不复制 README、不整段搬 spec、不为凑字数铺陈概念。
- **不炫技**：主读者是找实习的同学，架构与工程细节点到为止；想深挖的人给仓库链接。
- **不避坑**：踩坑内容（第六部分装不上怎么办、FAQ）必须给「现象 → 原因 → 怎么办」。
- **不反复喊 star**：全文引导不超过 2 次。

### 2.9 Star 与转化点

| 位置 | 形式 | 要求 |
| --- | --- | --- |
| 第一部分 1.3 | 首次给出仓库地址 + 「觉得有用顺手点个 star」 | 自然一句，和「当前状态」写在一起 |
| 第六部分结尾 | 用起来之后的一句「如果它帮到你」 | 可选，最多一句 |
| 第九部分 9.2 | 共建邀请 + star / PR | 收尾号召，语气轻松 |

### 2.10 事实校验规则

- 版本号、路径、字段名、错误码必须来自仓库文件，写时回查一次。
- 「是否已实现」以 `openspec/specs/` 与已归档 change 为准；在制 change 只能写「在制 / 未验收」。
- 截图与文字描述一致；未实机验收的图在 caption 标「设计中」。
- 发布前移除 `draft: true`，补齐 `summary` / `cardImage`。

## 3. 完整目录（10 部分）

### 第五部分 · 五个核心机制（它是怎么跑起来的）

> 本节回答：一场面试背后发生了什么？｜约 900 字｜图 1 张

- **5.1 双会话隔离**
  - 要点：会话 A 面试官 / 会话 B 教练；都用宿主已配置的模型，插件不另配 Key；A 看不见评分提示词，B 的输出不进气泡；材料单向 A → B。
  - 素材：`interview-session` spec、`archive/2026-09-17-interview-start-dual-session`。
  - 配图：`dual-session-flow.svg`（待生成）。
  - 篇幅：约 220 字。
- **5.2 开卷要点**
  - 要点：题目一出现就有开卷要点；题目由模型按主题动态生成，没有死题库。
  - 素材：`backend/src/services/coach-brief.ts`。
  - 篇幅：约 120 字。
- **5.3 追问与待答问抽取**
  - 要点：只在宿主输入框作答；插件不再催题，而是从对话里抽当前待答问（`【本题】` 标记 → 跳过文末议程句 → 最后一段连续问句）；面板「刷新本题」兜底。
  - 素材：`interview-follow-up` spec、`services/pending-question.ts`。
  - 篇幅：约 200 字。
- **5.4 问题卡片与交卷即评**
  - 要点：`Q1` / `Q1.1` / `Q2` 编号；一有新作答就给对照 + 五维（基础扎实度 / 原理理解 / 场景迁移 / 深度边界 / 表达清晰度，1–5 允许 .5）；追问新开卡，不覆写上一张；**前端不算分**。
  - 素材：`interview-cards` spec、`services/coach-score.ts`。
  - 篇幅：约 220 字。
- **5.5 结束本轮与落盘**
  - 要点：只发一句「结束面试」→ 面试官固定收尾句 → 工作区写出 `qa.md` + `summary.md` → 回入口；不摘人设、不切会话；同一条对话可再开一轮。
  - 素材：`interview-round-close` spec、`services/end-round.ts`。
  - 篇幅：约 140 字。

### 第八部分 · 它是怎么长期演进的：SDD 规范驱动的 Vibe Coding

> 本节回答：这项目怎么一步步长出来的？｜约 700 字｜图 0–1 张
> 口径：讲**这个项目实际怎么跑 SDD**，不写成通用方法论教程。

- **8.1 它不是一把梭写完的，而是 SDD 规范驱动的项目**
  - 要点：代码主要由 AI 产出（Vibe Coding），但每一步都被 SDD（规范驱动开发）的流程规范夹住——先写清「为什么改、改什么、怎么验收」，再让 AI 实现。正因为有这套规范，这个项目才敢长期演进，也才敢让别人接手共建。
  - 篇幅：约 220 字。
- **8.2 四份长期生效的规范文档**
  - `AGENTS.md`：全局硬约束（插件形态边界、增量开发、提交与评审）。
  - `docs/architecture/ARCHITECTURE.md`：分层、依赖方向、适配层、编码规范；改分层先改它。
  - `docs/product/REQUIREMENTS.md`：产品方向（**不是实现真源**，只用于校正方向）。
  - `docs/FORBIDDEN.md`：已否决做法与错误边界，防止反复踩同一个坑。
  - 另有一份 `interviewer-role-prompt.md` 作为面试官内容口径。
  - 篇幅：约 200 字。
- **8.3 一刀一能力：每步都有规格，每步都能验证**
  - 要点：`proposal`（Why / What Changes）→ `design`（取舍）→ `specs`（SHALL/MUST 场景）→ `tasks`（含验收项）→ 归档同步主规格；一刀只做一件事，禁止把还没验证的能力提前塞进来。
  - 篇幅：约 180 字。
- **8.4 也正因为这样，它还能继续往前长**
  - 要点：每一刀只做一件能说清、能验证的事，做完就归档、成为下一刀的地基。所以第九部分那些方向不是画饼，而是能照着同一套规范继续加的。
  - 篇幅：约 100 字。

### 第十部分 · FAQ

> 本节回答：高频疑问收口｜约 300 字｜图 0 张

- 为什么不在面板里直接聊天？——对话表面归宿主，插件不提供聊天。

## 第一部分 · 开场：练八股为什么要切出去

### 1.1 一个具体的练习场景

晚上十点，你刚在 DeepSeek Harness 里改完一段代码，想趁热练会儿八股。

于是你打开一个刷题网站，或者把一段「你是资深面试官」的 prompt 粘进对话里。答完之后——题目散在网页上，回答散在聊天记录里，第二天醒来什么都不剩。想复盘？只能往上翻，翻到哪算哪。

真正的问题不是「没有地方练」，而是三处断裂：

| 断裂 | 具体表现 |
| --- | --- |
| 环境断裂 | 你已经在 DSH 里写代码、对话、选模型，练八股却要切到另一个产品 |
| 角色混叠 | 面试官、标准答案、评分全挤在同一段气泡里，答完还得自己给自己打分 |
| 结果不留 | 面完就散，第二天全忘，复盘只能翻聊天记录 |

一句话：**练八股这件事，和你写代码的地方、和最后能留下来的东西，是断开的。**

### 1.2 一句话说清它是什么

`interview-dsh` 是跑在 DeepSeek Harness（DSH）上的**八股专项陪练插件**：考场对话当面试官，右侧面板当教练，问答落盘成能直接导入笔记库的 Markdown。

它有三个「不是」，先说清楚免得误会：

- **不是独立聊天应用**：说话只发生在 DSH 原本的对话里，面板里没有输入框、没有消息列表、没有气泡。
- **不是把面试官塞进你正在写代码的那条对话**：点开始后，它会在当前项目下**新开**一场考场会话，不污染你手上的上下文。
- **不是闭卷考场**：每题先给你开卷要点，答完立刻给对照和五维评分。这是陪练，目的不是考倒你，是让你当场知道差在哪。

### 1.3 开源地址、协议与当前状态

- 仓库：[NEEDS_REVIEW: 待确认最终地址]，MIT 协议，随便用、随便改。
- 当前只做**八股专项**（Java 并发 / MySQL / Redis / MQ / Spring 这些），项目深挖和混合模式暂时不做。
- 卡片流、滑动切题这部分的实机验收还在收尾，其余能力都已可用。

如果它帮到你了，顺手点个 star，我会很开心。

### 1.4 全文地图

先讲怎么装（第二部分），再讲它到底怎么用（第三部分），然后拆开五个核心机制（第五部分）、带你走完一场完整面试（第六部分），最后说练完的记录怎么变成能复习的资产（第七部分）。

读完你应该能做到两件事：**装上去开一场**，以及**把记录导进你的笔记库**。

## 第二部分 · 五分钟跑起来：前置条件与安装

### 2.1 DSH 一句话是什么

DeepSeek Harness 是一个**插件化的 Agent 底座**——它不是一个聊天应用，而是一个可以被长能力的运行时：会话、模型、工具、提示词装配、UI 插槽都由它提供，业务以插件的形式挂上去。

想深入了解可以看我的另一篇《用 DeepSeek Harness 写一个 Agent 插件》，这里不展开。

### 2.2 下载与安装 DSH

先从官方渠道装好 DSH Desktop 并启动一次。

本文的环境事实如下（换机器或升版本后请先复核）：

- DSH Desktop `0.2.17`（`com.yeagoo.dsh-desktop`）
- 实际加载的 harness 为 `@deepseek-ai/dsh 0.1.1-rc.2`

版本不一致时，最常出现的现象是「某些服务取不到」，后面 2.4 会说到。

### 2.3 安装本插件

```bash
git clone [NEEDS_REVIEW: 仓库地址]
cd interview-dsh
npm install
npm run build
dsh plugin add .
```

装的是**你当前正在使用的那个 profile**——如果你平时用多个 profile，记得确认装对了。

整个装配是声明式的：插件包里的 `cordis.patch.yml` 说明了要往 profile 里追加什么，DSH 启动时自动加载。**它不改 DSH 一行源码**，卸载也只是把这一行去掉。

### 2.4 怎么确认装好了

装完重载 DSH，看两件事：

1. **输入框右侧出现「面试」按钮**——这就是插件的入口；
2. **点它能打开面板**，能选主题和难度——这就算装好了。

如果你的环境没有右侧标签栏服务，插件会自动退回成一个右侧抽屉浮层，**这是正常行为，不是装失败**。

装不上时按这个顺序排查：profile 装错 → 构建产物没生成（`backend/dist`、`frontend/dist/client.js`）→ 版本不匹配。**不要靠新建 profile 或升级 Desktop 绕开**，那只会掩盖真正的原因。

## 第三部分 · 它到底是什么：三个表面与一场面试的形状

### 3.1 三个表面

![三个表面：输入栏按钮、考场对话、教练面板](./deepseek-harness-interview/assets/images/three-surfaces.svg)

| 表面 | 归属 | 角色 | 你感知到的 |
| --- | --- | --- | --- |
| 输入框右侧「面试」按钮 | 宿主 | 入口 | 点开面板，不做任何别的事 |
| 考场对话（新开的那条） | 宿主 | 面试官 | 提问、追问、提示、换题、结束 |
| 右侧插件面板 | 本插件 | 教练 | 开一场、看开卷要点、看对照与五维、切回已答卡 |

一句话记住：**说话在左边（宿主对话），看东西在右边（插件面板）。**

### 3.2 双会话：左边被面，右边对照

点「开始」之后是两条会话：

- **考场会话**：面试官在这里说话，你的回答也写在这里——用的是你当前会话已经配好的模型，**插件不让你另配 Key**。
- **教练会话**：它的产出只进面板。题目一出来，开卷要点立刻出现在右边。

为什么要分开？因为**面试官不该看见评分和标准答提示词**，你答题时也不该被答案污染。数据只单向流动：考场的问答作为材料交给面板，面板的东西绝不回流到考场，也绝不会变成气泡里的一段话。

![双会话与单向数据流](./deepseek-harness-interview/assets/images/dual-session-flow.svg)

### 3.3 开卷陪练，不是闭卷考场

题目是模型按你选的主题动态生成的，**没有预置题库**——所以你背不了题，只能真答。

每题的流程是：题目出现 → 面板给出开卷要点 → 你在宿主输入框作答 → 面板立刻给出「已覆盖 / 未覆盖 / 评语」和五维评分（基础扎实度、原理理解、场景迁移、深度边界、表达清晰度，1–5 分，允许 .5）。

面试官追问时，面板会**新开一张卡**（`Q1` → `Q1.1`），不会把上一题冲掉。

### 3.4 它现在不做什么

划清边界，免得你有错误期待：

- 只做八股专项，不做项目深挖、不做混合模式；
- 没有时长和倒计时，没有「提示 / 跳过」按钮；
- 不给场末长篇简报——简报就是那些能随时切回去看的逐题卡片；
- 面板不是阅读器，也不提供编辑器。

这些「不做」不是没做完，是**主动划的界**：先把「陪练」这一件事做扎实。

### 3.5 它是一个插件，不是一个应用

最后说一句定位：它是**长在 DSH 里的一块能力**，不是又一个独立的聊天产品。

面试陪练需要的会话、模型、提示词装配、文件读写、UI 插槽——DSH 全都已经有了，所以没必要再造一套 Agent 和 Harness，直接复用就行。插件只负责三件事：**面试规则、教练面板、档案落盘**。下一部分就讲这个判断。
