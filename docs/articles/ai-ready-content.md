# 为 AI 更新设计内容模型

一个作品集如果要被文件和 AI 持续更新，真正需要稳定的不是页面，而是内容边界。页面只是内容模型的一种投影。

## 问题从哪里开始

最常见的做法是把内容直接写进组件。它在第一版很快，但会带来三个问题：

1. 修改者需要理解页面结构；
2. 同一信息在多个位置重复出现；
3. AI 很难判断一段文本属于事实、摘要还是展示文案。

因此，我把个人资料、项目和文章摘要分别建模，再由组件决定如何呈现。

## 先确定稳定字段

项目对象不应该只包含标题、封面和链接。它还应回答面试官真正关心的问题：

```ts
interface Project {
  title: string
  background: string
  responsibilities: string[]
  architecture: string[]
  challenges: Array<{
    title: string
    description: string
  }>
  outcomes: string[]
}
```

这些字段与具体页面布局无关，因此首页卡片、项目列表和详情页可以共享同一份数据。

## 给自动更新留下约束

让 AI 直接“重写项目介绍”并不可靠。更稳妥的方式是限制它能修改的字段，并对输出做校验：

- 枚举字段必须来自已知集合；
- 日期使用统一格式；
- 链接必须是内部路径或合法 URL；
- 成果必须能追溯到项目证据，不能生成没有依据的数字；
- 修改后必须通过类型检查与站点构建。

## 人与 AI 的职责边界

AI 适合完成格式归一、摘要提取和候选标签推荐；求职方向、项目成果和经历事实仍应由本人确认。自动化提高更新速度，但不能替代事实责任。

## 最后的判断标准

一个内容模型是否有效，可以用三个问题检查：

1. 新增项目时，是否只需添加数据而不改组件？
2. 同一事实修改后，所有页面是否同步更新？
3. 自动化产生错误时，能否在构建阶段被发现？

如果答案都是肯定的，这个站点才真正具备持续维护能力。
