# VitePress + Teek 的作品集实践

VitePress 很适合技术内容，Teek 又补充了文章信息、代码块和知识导航。挑战在于：作品集首页需要更强的信息设计，不能只是文档主题的默认 Hero。

## 为什么保留主题

从零重做文章系统意味着要重新处理目录、代码高亮、上一篇与下一篇、搜索、移动端导航和暗色模式。这些都不是作品集的差异化价值。

因此我的边界是：

- 文章页沿用 Teek；
- 导航与语义色沿用 VitePress；
- 首页、经历和项目页使用自定义 Vue 组件；
- 所有内容继续从 Markdown 或 TypeScript 数据读取。

## 页面如何选择布局

自定义页面使用 `layout: page`，避免主题把它识别为普通文章：

```md
---
layout: page
sidebar: false
aside: false
---

<ProjectsPage />
```

文章不声明自定义布局，因此会保留右侧目录、代码块和文档页脚。

## 视觉一致性来自令牌

自定义组件不复制主题内部 DOM，而是对齐几个稳定的视觉变量：品牌色、页面背景、正文色、边框色和导航高度。这样主题升级时，自定义层更不容易被实现细节绑住。

```css
:root {
  --xa-brand: #0f766e;
  --xa-text: #15201f;
  --xa-surface: #ffffff;
  --xa-border: #dfe8e6;
}
```

暗色模式只需重新映射语义令牌，不必逐个修改组件。

## 响应式不是缩小桌面版

移动端优先保留姓名、方向、状态、项目和联系方式；辅助统计卡随后出现。项目筛选采用可换行按钮，架构流程从横向改为纵向，所有触控目标保持至少 44 像素。

## 结论

这个组合的价值不是“主题更好看”，而是把精力放在真正影响求职判断的页面上，同时让长文阅读和后续维护继续受益于成熟主题。
