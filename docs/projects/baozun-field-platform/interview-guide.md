## 面试导读

> 这一节不是"背答案"，而是把"怎么把项目讲清楚"的方法沉淀下来：实习讲解怎么说、简历怎么写、高频追问怎么接。

---

## 实习讲解怎么说

把 90 秒讲清楚，比讲满 10 分钟更有效。建议用"问题 → 做法 → 结果 → 反思"的结构：

1. **问题**：业务页面上的字段散落、定义漂移、改造返工。
2. **做法**：把页面字段采集为证据，用受限 Agent 解析成候选字段树，沉淀为可治理的目录，再异步交付字段字典。
3. **结果**：字段可检索、可比对、可复用；页面改造时变更可追踪。
4. **反思**：采集覆盖、解析验收、交付一致性，每一环都有权衡。

如果只讲一个点，讲"字段从散落到可治理"这件事。

## 简历怎么写

简历里不要写"负责字段平台"，要写"做了什么、边界在哪、权衡是什么"：

- **做了什么**：设计字段证据契约；实现 DOM-first 采集与受限 Agent 解析；落地目录树一致性与异步字典导出。
- **边界在哪**：我只负责"字段从页面到目录"这一段；下游消费、页面前端不在我的范围。
- **权衡是什么**：人工录入快但易漂移，自动解析稳但需验收；我用"人工 + 自动双入口"收敛。

关键词建议：**字段证据契约、DOM-first 采集、受限 Agent、目录树一致性、异步字典交付**。

## 高频追问怎么接

面试官常问的几类问题，以及接法：

### 1. "为什么不用纯人工录入？"

人工录入快、准、可控，但**不可规模、易漂移、难审计**。当页面字段上千、改造频繁时，人工维护成本指数上升。所以我把人工作为"入口之一"，用自动解析承接规模，用证据契约保一致。

### 2. "Agent 解析为什么是'受限'的？"

因为页面内容不可信、不可控。受限指：**输入受约束（只吃证据）、动作受约束（只产出候选树）、验证受约束（必须可验收）**。不是让 Agent 自由发挥，而是把它框在"可验收"的边界里。

### 3. "目录树一致性怎么保证？"

不靠事后比对，而靠**结构不变量**：每个节点有唯一父级、祖先链可推导、兄弟有序。写入时维护直接父级关系，查询时按需展开祖先链；并发写入用 CAS / 版本号兜住。

### 4. "异步导出为什么不直接同步返回？"

因为字段字典可能很大、消费方很多。同步返回会拖垮写入链路。所以导出是**独立任务**：从一致性快照流式写入，状态可查、失败可重试、交付原子。

### 5. "页面一改，目录怎么办？"

再采集，拿到新快照，和旧快照做**变化集**，匹配身份后表达增删改，人工审核后发布。目录不是一次性产物，而是"长青"的资产。

> 一句话收尾：这个项目的本质，是把"散落的字段"变成"可治理的资产"，而工程难点全在"如何在不信任的输入上，交付可信任的结构"。
