## 关联关系

项目有四个相互咬合的主问题。第一条是 Agent 装配，解释能力从配置进入运行时；第二条是 SSH 主链路，解释副作用如何被准入和执行；第三条是状态与恢复，解释长任务输出如何被持久化、读取和找回；第四条是隔离与运维，解释谁可以看到什么、在哪个环境执行以及重启后能恢复什么。

阅读时不要把 `tools/list` 当成权限系统，也不要把 Redis 记录当成远端执行本身。前者只是发现结果，真正调用仍需再次检查；后者保存元数据和输出游标，但没有远端 Shell 的进程上下文。

## 文档内统一词义

| 词 | 本项目中的含义 |
| --- | --- |
| 连接 | 数据库中保存的远端 SSH 连接配置，以及进程内可用的 JSch Session |
| 执行 | 一个有 executionId、执行上下文、目标类型、状态和输出游标的命令生命周期 |
| 终端 | 页面侧可交互的运行时资源；外部 Agent 终端属于观察型资源 |
| 工具 | 内置 Spring AI 工具或动态 MCP、Skills 工具；工具本身不绕过 Case 和 Domain |
| 会话 | HTTP Agent 聊天会话、MCP transport 会话或运行时上下文；它们不是同一个概念 |
| Sandbox | 目标 SSH 服务器上的 Docker 隔离执行环境，不是 SSH 连接的替代品 |
