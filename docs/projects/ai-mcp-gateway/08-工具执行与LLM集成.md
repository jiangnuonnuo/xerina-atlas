# 工具执行与 LLM 集成：模型选择工具，网关决定能否执行

![AI 工具调用](./assets/llm-loop.gif)

图要回答的问题：LLM 如何从已发布工具中选择能力，以及网关怎样把统一的 MCP 工具调用分派到不同执行端口。

## LLM 在系统中的位置

LLM 负责理解用户意图、发现工具、生成 arguments 和组织最终回答。它不负责判断数据库凭证是否正确，也不负责决定一个工具是否属于当前能力包。授权、作用域、限流和安全校验都由网关执行。

## 工具调用入口

`ToolInvocationService` 先校验网关、工具名和 arguments，再根据工具配置查询协议类型。策略工厂选择对应策略，当前包括 HTTP、数据源和上游 MCP 三类执行方向。

这种设计让 MCP 工具对外保持统一契约，内部协议可以独立演进。新增一种执行来源时，只需要增加策略和端口实现，不需要把协议判断散落在消息处理器和 Controller 中。

## 结果和轨迹

下游结果经过统一的领域结果对象返回，工具调用记录保存调用信息、成功状态和错误信息。记录轨迹用于测试、诊断和运行观察，但不应把内部连接信息或敏感凭证写入日志。

## LLM 失败和工具失败

模型无法生成有效 arguments 属于编排失败；工具不存在或不在发布作用域属于能力失败；安全责任链拒绝属于准入失败；HTTP、MySQL、Redis 或上游 MCP 超时属于执行失败。区分这些失败，客户端才能决定是否重试、换工具或重新授权。
