# 认证、权限与隔离：让 AI 只看到它被授予的能力

![运行时隔离边界](./assets/isolation.gif)

图要回答的问题：一次 MCP 调用如何依次通过凭证、网关、能力包、会话、工具和数据源边界。隔离不是某一个 Filter，而是多个领域事实共同完成的结果。

## 网关隔离

`gatewayId` 是配置、协议、工具、能力包和会话的基本归属。查询和执行都必须带当前网关上下文，不能因为工具名相同就跨网关复用配置。

## 能力包隔离

运行时 `tools/list` 根据会话绑定的授权作用域返回发布工具；`tools/call` 还要再次校验工具是否属于该作用域。只在列表层过滤是不够的，因为客户端可以绕过列表直接构造工具名。

## 会话隔离

会话绑定 gateway、transport 和授权上下文。后续 POST、GET、DELETE 不能只验证 session id，还要验证路径网关和会话元数据一致。会话过期、删除或 scope 不匹配时，调用必须在执行前结束。

## 令牌隔离

包级访问令牌使用公开 token id 和 HMAC 摘要进行认证，记录过期时间、状态和限流配置。原始令牌只在签发时返回，不应持久化明文。Streamable HTTP 使用 Authorization Bearer，旧 SSE 只保留兼容型 API Key 路径。

## 数据源隔离

数据源凭证使用 AES-GCM 加密保存，密钥只从启动环境或密钥管理系统注入。数据源执行前检查启用状态、来源类型、操作白名单、写权限、结构参数、超时和最大返回量。

## 管理权限与运行权限

当前工程重点实现的是网关运行授权、能力包令牌和数据源安全边界，不应夸大为已经完成完整企业 RBAC。生产环境仍应在管理面前增加组织、角色、审批和审计体系，并把它们映射到能力包发布权限。
