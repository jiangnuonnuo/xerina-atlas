# 一致性、多实例与部署：区分事实、投影和连接资源

![多实例运行边界](./assets/multi-instance-boundary.gif)

图要回答的问题：多个网关实例如何共享配置事实、会话元数据和运行时能力，以及当前实现在哪个地方仍然依赖实例内存。

## 三类状态

| 状态 | 存储 | 生命周期 | 角色 |
| --- | --- | --- | --- |
| 配置事实 | MySQL | 长期 | 网关、工具、协议、能力包和令牌 |
| 运行时投影 | Redis | 可重建 | 已发布工具、版本和脏标记 |
| 连接资源 | 本地内存 + Redis 元数据 | 租约 | Sink、会话上下文、事件序列 |

## 发布一致性

发布事务先保证 MySQL 事实完整，再通过事务同步点刷新或标记 Redis。锁租约只保护缓存重建并发，不承担业务幂等；空结果使用短 TTL，正常结果使用 TTL 和抖动，脏标记用于阻止继续使用旧投影。

## 会话同步

实例启动时从 Redis 恢复有效会话元数据，过期元数据被清理；Redis Topic 将会话同步事件转发给其他实例。实例本地重新创建 Sink 后，才能继续承载当前 JVM 的事件流。

## 多实例限制

Redis 会话元数据可以共享，但当前 replay buffer 是内存实现，事件本身不能可靠地跨实例读取。因此生产水平扩展必须补充共享 replay 存储，或者明确负载均衡粘性和故障后的重新初始化策略。

## 部署边界

部署资料包含 Docker Compose、MySQL 初始化/升级脚本、应用启动脚本和 Nginx 管理端。生产环境必须通过环境变量或密钥服务注入数据库、Redis、LLM、AES 和 HMAC 配置，不能沿用开发环境中的固定密码和 API Key。
